# AI PR Review Assistant 模块拆分与开发计划

## 一、文档说明

本文档用于记录项目的开发拆分思路、阶段目标和当前完成状态。

本项目最初采用“按模块逐步推进”的方式开发，目的是保证每一轮改动都尽量独立、可验证、可运行。当前项目已经完成前后端主流程、数据持久化、AI Review 链路、统一校验与异常处理，并已具备作为完整全栈项目交付和演示的条件。

因此，原本单独规划的“第十二模块：文档与演示材料”不再作为独立开发阶段保留，相关内容已经直接并入当前仓库文档交付。

## 二、开发拆分原则

开发过程中遵循以下原则：

- 每个阶段只解决一个核心问题
- 保持主分支始终可启动、可运行
- 优先保证前后端链路完整，再逐步补齐质量能力
- 对外部依赖调用、参数校验和错误处理进行显式设计

## 三、模块划分

项目开发共拆分为以下 11 个模块：

```text
1. 项目基础结构
2. 后端基础服务
3. 前端基础页面
4. 数据库与实体模型
5. GitHub PR 数据获取
6. Diff 解析与上下文构建
7. AI 模型调用
8. AI Review 分析
9. Review 任务接口
10. 前端 Review 工作流与结果展示
11. 参数校验与统一异常处理
```

## 五、当前项目状态

截至目前，项目已经具备完整全栈能力：

- 前端可提交 PR Review 请求并展示完整结果
- 后端可完成 GitHub 获取、Diff 解析、AI 调用、结果落库和结果查询
- 参数校验、统一异常处理和错误提示已接入完整链路
- 后端测试可运行，前端可完成构建验证

这意味着项目已经不再是“开发中半成品”，而是一个可本地运行、可演示、可继续迭代的完整前后端项目。

## 六、关于原第十二模块

原规划中的“文档与演示材料”不再保留为独立模块，原因如下：

- 当前 README 已直接承担完整项目说明职责
- `docs/` 目录已经包含需求、技术选型、架构、数据库和开发计划等核心文档
- 项目当前重点应转向功能迭代、部署、性能优化或产品化，而不是继续按模块补开发框架

如后续继续演进，建议以“版本迭代”而不是“补模块”的方式推进，例如：

- 异步任务化
- 私有仓库支持
- GitHub Review Comment 回写
- Docker 化部署
- 多模型切换
- 更丰富的检索上下文能力

## 七、交付建议

当前仓库适合作为完整项目进行展示和交付。建议后续维护方向：

- 保持 README 与实际运行方式同步
- 所有新功能优先补测试与错误处理
- 严格通过环境变量或本地忽略文件管理密钥
- 如果引入部署方案，补充 Docker 或云平台文档

## 八、总结

本项目已完成从基础结构到 AI Review 主流程，再到统一校验与异常处理的完整建设。

模块化开发目标已经达成，当前阶段不再保留独立的第十二模块。仓库现状应视为“完整项目文档已并入当前交付”的稳定版本。
