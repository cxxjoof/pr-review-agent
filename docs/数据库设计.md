# AI PR Review 助手数据库设计文档

## 一、文档说明

本文档用于说明 AI PR Review 助手项目的数据库设计。系统主要功能是用户输入 GitHub 仓库地址和 PR 编号后，后端自动获取 PR 信息、解析代码变更、调用 AI 模型分析，并生成 PR 变更总结、风险代码识别、Review 建议和测试建议。

本项目后端采用 Java + Spring Boot，数据库采用 MySQL。数据库主要用于保存 Review 分析任务、Pull Request 基本信息、AI 分析结果、风险代码项和模型调用记录。

## 二、数据库设计目标

数据库设计需要满足以下目标：

1. 能够保存用户提交的 PR Review 分析任务；
2. 能够记录每个任务的执行状态；
3. 能够保存 GitHub PR 的基本信息；
4. 能够保存 AI 生成的 Review 报告；
5. 能够保存风险代码识别结果；
6. 能够记录模型调用日志，方便后续排查问题；
7. 能够支持历史 Review 记录查询；
8. 方便后续扩展用户系统、私有仓库、GitHub 自动评论和团队规则配置。

## 三、数据库选型

本项目选择 MySQL 作为主要数据库。

选择 MySQL 的原因：

1. 使用广泛，生态成熟；
2. 与 Java Spring Boot 集成方便；
3. 适合存储结构化业务数据；
4. 支持事务、索引和复杂查询；
5. 适合项目后续扩展为多人使用的 Web 系统。

开发阶段也可以使用 H2 或 SQLite 进行快速测试，但正式项目建议使用 MySQL。

## 四、数据库整体表结构

本项目第一版主要设计 5 张核心表：

```text
review_task          Review 分析任务表
pull_request_info    Pull Request 基本信息表
review_result        AI Review 结果表
risk_item            风险代码项表
model_call_log       模型调用日志表
```

表之间的关系如下：

```text
review_task 1 —— 1 pull_request_info
review_task 1 —— 1 review_result
review_task 1 —— N risk_item
review_task 1 —— N model_call_log
```

也就是说，一个 Review 任务对应一个 PR 基本信息，一个最终 Review 报告，多个风险项，以及多条模型调用记录。

## 五、核心实体关系说明

### 1. review_task 与 pull_request_info

`review_task` 表保存任务本身的信息，例如仓库地址、PR 编号、任务状态等。

`pull_request_info` 表保存从 GitHub API 获取到的 PR 详细信息，例如 PR 标题、作者、分支、修改文件数量、新增行数和删除行数等。

二者是一对一关系。

### 2. review_task 与 review_result

`review_result` 表保存 AI 最终生成的分析报告，包括变更总结、Review 建议、测试建议和总体评价。

一个任务最终生成一份 Review 报告，所以二者是一对一关系。

### 3. review_task 与 risk_item

`risk_item` 表保存 AI 识别出的风险代码项。一个 PR 中可能存在多个风险项，所以一个任务对应多个风险项。

二者是一对多关系。

### 4. review_task 与 model_call_log

AI 分析过程中可能多次调用模型，例如先生成变更总结，再分析风险代码，最后生成整体报告。因此一个任务可能对应多条模型调用日志。

二者是一对多关系。

## 六、数据表设计

## 1. Review 分析任务表：review_task

### 表说明

该表用于保存用户提交的 Review 分析任务，是整个数据库的核心主表。

### 字段设计

| 字段名           | 类型           | 约束        | 说明          |
| ------------- | ------------ | --------- | ----------- |
| id            | bigint       | 主键，自增     | 任务 ID       |
| repo_url      | varchar(500) | not null  | GitHub 仓库地址 |
| repo_owner    | varchar(100) | not null  | 仓库拥有者       |
| repo_name     | varchar(100) | not null  | 仓库名称        |
| pr_number     | int          | not null  | PR 编号       |
| status        | varchar(30)  | not null  | 任务状态        |
| risk_count    | int          | default 0 | 风险项数量       |
| error_message | text         | null      | 失败原因        |
| created_at    | datetime     | not null  | 创建时间        |
| updated_at    | datetime     | not null  | 更新时间        |

### 状态说明

`status` 字段可选值：

```text
PENDING：任务已创建，等待分析
RUNNING：任务正在分析
SUCCESS：任务分析成功
FAILED：任务分析失败
```

### 建表 SQL

```sql
CREATE TABLE review_task (
    id BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '任务ID',
    repo_url VARCHAR(500) NOT NULL COMMENT 'GitHub仓库地址',
    repo_owner VARCHAR(100) NOT NULL COMMENT '仓库拥有者',
    repo_name VARCHAR(100) NOT NULL COMMENT '仓库名称',
    pr_number INT NOT NULL COMMENT 'PR编号',
    status VARCHAR(30) NOT NULL COMMENT '任务状态：PENDING/RUNNING/SUCCESS/FAILED',
    risk_count INT DEFAULT 0 COMMENT '风险项数量',
    error_message TEXT NULL COMMENT '失败原因',
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    INDEX idx_repo_pr (repo_owner, repo_name, pr_number),
    INDEX idx_status (status),
    INDEX idx_created_at (created_at)
) COMMENT='Review分析任务表';
```

    id BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT 'PR信息ID',
    task_id BIGINT NOT NULL COMMENT '关联任务ID',
    github_pr_id BIGINT NULL COMMENT 'GitHub PR ID',
    title VARCHAR(500) NULL COMMENT 'PR标题',
    description TEXT NULL COMMENT 'PR描述',
    author VARCHAR(100) NULL COMMENT 'PR作者',
    source_branch VARCHAR(200) NULL COMMENT '源分支',
    target_branch VARCHAR(200) NULL COMMENT '目标分支',
    state VARCHAR(30) NULL COMMENT 'PR状态',
    changed_files INT DEFAULT 0 COMMENT '修改文件数量',
    additions INT DEFAULT 0 COMMENT '新增代码行数',
    deletions INT DEFAULT 0 COMMENT '删除代码行数',
    commits INT DEFAULT 0 COMMENT '提交数量',
    pr_url VARCHAR(500) NULL COMMENT 'PR页面地址',
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    UNIQUE KEY uk_task_id (task_id),
    CONSTRAINT fk_pr_info_task
        FOREIGN KEY (task_id) REFERENCES review_task(id)
        ON DELETE CASCADE

## 3. AI Review 结果表：review_result

### 表说明

该表用于保存 AI 生成的最终 Review 报告。

主要包括 PR 变更总结、涉及模块、Review 建议、测试建议、总体评价和 AI 原始返回内容。

### 字段设计

| 字段名                | 类型       | 约束       | 说明        |
| ------------------ | -------- | -------- | --------- |
| id                 | bigint   | 主键，自增    | 结果 ID     |
| task_id            | bigint   | not null | 关联任务 ID   |
| summary            | text     | null     | PR 变更总结   |
| changed_modules    | json     | null     | 涉及模块      |
| review_suggestions | json     | null     | Review 建议 |
| test_suggestions   | json     | null     | 测试建议      |
| overall_conclusion | text     | null     | 总体评价      |
| raw_ai_response    | longtext | null     | AI 原始返回结果 |
| created_at         | datetime | not null | 创建时间      |
| updated_at         | datetime | not null | 更新时间      |

### 字段说明

`changed_modules`、`review_suggestions`、`test_suggestions` 使用 JSON 类型保存，方便存储数组结构。例如：

```json
["登录模块", "权限校验模块", "配置文件"]
```

```json
[
  "建议补充异常处理",
  "建议增加接口参数校验",
  "建议补充单元测试"
]
```

### 建表 SQL

```sql
CREATE TABLE review_result (
    id BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT 'Review结果ID',
    task_id BIGINT NOT NULL COMMENT '关联任务ID',
    summary TEXT NULL COMMENT 'PR变更总结',
    changed_modules JSON NULL COMMENT '涉及模块',
    review_suggestions JSON NULL COMMENT 'Review建议',
    test_suggestions JSON NULL COMMENT '测试建议',
    overall_conclusion TEXT NULL COMMENT '总体评价',
    raw_ai_response LONGTEXT NULL COMMENT 'AI原始返回结果',
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    UNIQUE KEY uk_task_id (task_id),
    CONSTRAINT fk_review_result_task
        FOREIGN KEY (task_id) REFERENCES review_task(id)
        ON DELETE CASCADE
) COMMENT='AI Review结果表';
```

## 4. 风险代码项表：risk_item

### 表说明

该表用于保存 AI 识别出的具体风险项。一个 PR 可能有多个风险项。

### 字段设计

| 字段名          | 类型           | 约束       | 说明      |
| ------------ | ------------ | -------- | ------- |
| id           | bigint       | 主键，自增    | 风险项 ID  |
| task_id      | bigint       | not null | 关联任务 ID |
| file_path    | varchar(500) | not null | 文件路径    |
| line_number  | int          | null     | 代码行号    |
| code_snippet | text         | null     | 相关代码片段  |
| risk_level   | varchar(30)  | not null | 风险等级    |
| risk_type    | varchar(100) | null     | 风险类型    |
| description  | text         | null     | 风险描述    |
| suggestion   | text         | null     | 修改建议    |
| confidence   | decimal(5,2) | null     | AI 置信度  |
| created_at   | datetime     | not null | 创建时间    |

### 风险等级说明

`risk_level` 字段可选值：

```text
HIGH：高风险，需要优先处理
MEDIUM：中风险，建议修改或人工确认
LOW：低风险，主要是代码规范、可读性或优化建议
```

### 风险类型示例

`risk_type` 可选值可以包括：

```text
NULL_POINTER：空指针风险
EXCEPTION_HANDLING：异常处理缺失
SECURITY：安全风险
PERFORMANCE：性能风险
INPUT_VALIDATION：输入校验不足
DATABASE：数据库操作风险
CONFIG_CHANGE：配置变更风险
TEST_MISSING：测试缺失
CODE_STYLE：代码风格问题
OTHER：其他问题
```

### 建表 SQL

```sql
CREATE TABLE risk_item (
    id BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '风险项ID',
    task_id BIGINT NOT NULL COMMENT '关联任务ID',
    file_path VARCHAR(500) NOT NULL COMMENT '文件路径',
    line_number INT NULL COMMENT '代码行号',
    code_snippet TEXT NULL COMMENT '相关代码片段',
    risk_level VARCHAR(30) NOT NULL COMMENT '风险等级：HIGH/MEDIUM/LOW',
    risk_type VARCHAR(100) NULL COMMENT '风险类型',
    description TEXT NULL COMMENT '风险描述',
    suggestion TEXT NULL COMMENT '修改建议',
    confidence DECIMAL(5,2) NULL COMMENT 'AI置信度',
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    INDEX idx_task_id (task_id),
    INDEX idx_risk_level (risk_level),
    INDEX idx_file_path (file_path),
    CONSTRAINT fk_risk_item_task
        FOREIGN KEY (task_id) REFERENCES review_task(id)
        ON DELETE CASCADE
) COMMENT='风险代码项表';
```

## 5. 模型调用日志表：model_call_log

### 表说明

该表用于记录每次调用 AI 模型的情况，方便后续排查模型调用失败、统计调用成本和优化 Prompt。

### 字段设计

| 字段名               | 类型           | 约束        | 说明         |
| ----------------- | ------------ | --------- | ---------- |
| id                | bigint       | 主键，自增     | 日志 ID      |
| task_id           | bigint       | not null  | 关联任务 ID    |
| model_name        | varchar(100) | not null  | 模型名称       |
| call_type         | varchar(100) | not null  | 调用类型       |
| prompt_tokens     | int          | default 0 | 输入 token 数 |
| completion_tokens | int          | default 0 | 输出 token 数 |
| total_tokens      | int          | default 0 | 总 token 数  |
| success           | tinyint      | not null  | 是否成功       |
| error_message     | text         | null      | 错误信息       |
| latency_ms        | int          | null      | 调用耗时，单位毫秒  |
| created_at        | datetime     | not null  | 创建时间       |

### 调用类型说明

`call_type` 可选值：

```text
SUMMARY：生成 PR 变更总结
RISK_DETECT：识别风险代码
SUGGESTION：生成 Review 建议
FINAL_REPORT：生成最终报告
```

### 建表 SQL

```sql
CREATE TABLE model_call_log (
    id BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '模型调用日志ID',
    task_id BIGINT NOT NULL COMMENT '关联任务ID',
    model_name VARCHAR(100) NOT NULL COMMENT '模型名称',
    call_type VARCHAR(100) NOT NULL COMMENT '调用类型',
    prompt_tokens INT DEFAULT 0 COMMENT '输入token数',
    completion_tokens INT DEFAULT 0 COMMENT '输出token数',
    total_tokens INT DEFAULT 0 COMMENT '总token数',
    success TINYINT NOT NULL COMMENT '是否成功：1成功，0失败',
    error_message TEXT NULL COMMENT '错误信息',
    latency_ms INT NULL COMMENT '调用耗时，单位毫秒',
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    INDEX idx_task_id (task_id),
    INDEX idx_model_name (model_name),
    INDEX idx_call_type (call_type),
    CONSTRAINT fk_model_call_task
        FOREIGN KEY (task_id) REFERENCES review_task(id)
        ON DELETE CASCADE
) COMMENT='模型调用日志表';
```

## 七、表关系设计

### 1. 关系说明

```text
review_task 是主表，其他表都通过 task_id 关联 review_task。
```

具体关系：

```text
review_task.id = pull_request_info.task_id
review_task.id = review_result.task_id
review_task.id = risk_item.task_id
review_task.id = model_call_log.task_id
```

### 2. 关系图说明

```text
review_task
   │
   ├── pull_request_info
   │       一个任务对应一个 PR 信息
   │
   ├── review_result
   │       一个任务对应一个 AI Review 报告
   │
   ├── risk_item
   │       一个任务对应多个风险项
   │
   └── model_call_log
           一个任务对应多条模型调用日志
```

## 八、索引设计

为了提高查询效率，需要设计必要索引。

### 1. review_task 表索引

```text
idx_repo_pr(repo_owner, repo_name, pr_number)
```

用于根据仓库和 PR 编号查询历史分析记录。

```text
idx_status(status)
```

用于查询不同状态的任务，例如 RUNNING、FAILED。

```text
idx_created_at(created_at)
```

用于按时间倒序查询历史任务。

### 2. risk_item 表索引

```text
idx_task_id(task_id)
```

用于查询某个任务下的所有风险项。

```text
idx_risk_level(risk_level)
```

用于按风险等级筛选高风险、中风险、低风险问题。

```text
idx_file_path(file_path)
```

用于后续按文件路径查询风险项。

### 3. model_call_log 表索引

```text
idx_task_id(task_id)
```

用于查询某个任务的模型调用记录。

```text
idx_model_name(model_name)
```

用于统计不同模型的调用情况。

```text
idx_call_type(call_type)
```

用于统计不同分析阶段的模型调用情况。

## 十二、数据写入流程

用户提交 PR 后，数据库写入流程如下：

```text
1. 创建 review_task 记录，状态为 PENDING
2. 开始分析后，将状态更新为 RUNNING
3. 调用 GitHub API，写入 pull_request_info
4. 调用 AI 模型，写入 model_call_log
5. 解析 AI 返回结果，写入 review_result
6. 保存风险项，写入 risk_item
7. 统计风险数量，更新 review_task.risk_count
8. 分析成功后，将 review_task.status 更新为 SUCCESS
9. 如果任意步骤失败，将 review_task.status 更新为 FAILED，并写入 error_message
```

## 十三、数据查询流程

前端查询 Review 结果时，后端查询流程如下：

```text
1. 根据 task_id 查询 review_task
2. 根据 task_id 查询 pull_request_info
3. 根据 task_id 查询 review_result
4. 根据 task_id 查询 risk_item 列表
5. 组装成 ReviewResultResponse
6. 返回给前端展示
```

返回给前端的数据结构大致如下：

```json
{
  "task": {},
  "pullRequest": {},
  "reviewResult": {},
  "riskItems": []
}
```

## 十四、数据安全设计

数据库中可能保存 PR 信息、AI 分析结果和部分代码片段，因此需要注意数据安全。

主要措施包括：

1. 不保存 GitHub Token 和模型 API Key；
2. 密钥只通过环境变量或配置中心读取；
3. 日志中不打印敏感信息；
4. 私有仓库分析结果后续需要增加用户权限控制；
5. 可对 raw_ai_response 和 code_snippet 控制保存长度；
6. 对长期不用的历史分析数据可定期清理；
7. 后续支持用户删除分析记录。

## 十六、数据库设计总结

本项目数据库以 `review_task` 为核心主表，通过 `task_id` 关联 PR 信息、AI 分析结果、风险项和模型调用日志。这样的设计结构清晰，能够完整支撑 AI PR Review 助手第一版核心功能。

第一版重点保存以下内容：

```text
任务信息
PR 基本信息
AI Review 报告
风险代码项
模型调用日志
```

该设计既能满足当前“输入 PR → 获取 diff → AI 分析 → 展示报告”的核心链路，也为后续扩展私有仓库、多用户系统、GitHub 自动评论、团队规则配置和模型调用成本统计预留了空间。
